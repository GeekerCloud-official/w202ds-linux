2026-11-07 修复 NV 工作副本被截短的问题：匹配本机二进制的原厂 `cp_diskserver` 以 `O_TRUNC` 打开 NV 后只写脏扇区，直接替换为普通文件会丢掉未改写的数据。现在原厂服务访问四个私有 loop 块设备，底层仍是 Linux 自己的完整 NV 镜像，不暴露物理 eMMC。已从本机校验有效的原厂 NV 只读恢复工作镜像，普通重启后 5G 注册、NM 自动连接、蜂窝 DNS、校验证书的 HTTPS 200 和后续 NV 保存均通过；四个原厂 NV 分区的整分区哈希前后相同。本轮没有证据能确定更早是谁操作过原厂分区，不能由工作文件损坏推断原厂分区被改坏。断电冷启动及长期稳定性仍待验收。

2026-11-07（北京时间）：修复 KDE 标准版迁移漏装的账号、AT 工具、属性及 AVB 输入。账号由 sysusers 分配，本机 UID/GID 为 985，避免原 989 与 dnsmasq 冲突；NV 镜像归 root，私有 loop 入口仅允许基带账号读写。可用 `W202_MODEM_FIRMWARE_DIR` 指定五个不可变运行输入的目录，并只读绑定到私有根。内核、驱动模块、原厂 loader/diskserver 二进制及引导分区未更换。

STA 联网策略为 Wi-Fi 优先（600）、蜂窝备用（900），蜂窝连接设为自动启动；2026-11-07 用户确认热点测速走蜂窝流量，蜂窝联网与 NM shared 热点共享链路验收通过。663／103 Mbps 是该链路的端到端结果，不是独立的 Wi-Fi 局域网吞吐。完整冷启动、射频掉网恢复、长时间稳定性和信号条准确性尚未验证。构建见 [用户态说明](userspace/README.md)，安装及桌面接入见 [集成说明](userspace/integration/README.md)。固定运行包及验证记录保留在本地 `userspace/releases/`，不上传 GitHub。
